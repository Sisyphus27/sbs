# 离线手机端 UI 重设计

日期: 2026-07-24
状态: 已批准
范围: `webapp/templates/week_export.html`（离线只读导出页)

## 背景

桌面 webui 已重设计（ADR 0006 极简工具风，见 `static/app.css`）。离线手机导出页 `week_export.html` 仍是旧内联样式：所有字段同权重、小灰字密排、重量这个最关键数字埋在 `.meta` 里。本次从第一性原理重构，非补丁式套样式。

## 第一性原理

此页存在为答一个问题：**"此刻在健身房，这个动我该上多重、做几次？"**

三个硬约束决定形态：

| 约束 | 推论 |
|---|---|
| 真离线 | 单文件、零请求、零依赖。是特征不是限制。 |
| 只读快照 | 数据回路在桌面（`末组` 输入 + 提交）。手机端刻意无编辑。 |
| 扫读非精读 | 健身房：汗、弱光、组间几秒、常戴护腕。扫一眼 > 读一段。 |

使用动线（每个箭头是摩擦点）:

```
开文件 → 定位今天 Day → 找当前动作 → 读重量+次数 → 上片 → 组间扫下组/下个动作
```

关键洞察：这是**装片清单**，不是数据表。健身房认知单位 = **"多重 × 几 × 几"**。其余字段（mode、est1RM、streak、rep-out target）是次级上下文 — 此刻不换一片铁。

## 设计原则

1. **重量即标题** — 该动作最大最粗，mono。
2. **方案即一行** — `几 × 几`（+ rep-out/streak，仅因决定你做到哪）。
3. **其余折叠为注脚** — mode/est1RM 缩成一行小字。
4. **Day 即导航** — 健身房一次只练一天，定位要快。
5. **弱光可读** — 对比、字号、深色模式。

## 架构

改一个模板 `week_export.html`，零路由改动。`_by_day`（`webapp/routes/plan.py:49`）已供全部数据：`weight/working_weight/reps/sets/repout/target/streak/est1rm/logged/is_bodyweight`。**无 Python 逻辑改动** — 纯模板 + 内联 CSS + 少量内联 JS。离线单文件本质保留。

### "默认展开哪个 day" 判定

设置只有 `week` + `days_per_week`，无"今天星期几"。离线单文件无可靠实时日历（服务器不知你哪天练；浏览器 `Date` 需维护易错的星期→训练日映射）。故用现有 `logged` 数据推：

- 第一个"部分动作未填"的 day = 进行中 day，默认展开。
- 全未填 → Day 1。
- 全填完 → 最后 day。

模板内 Jinja 计算，无需新字段、无不可靠日历猜测。

## 组件

```
Week N 计划                    [🌙 深色切换]
─────────────────────────────
[Day1][Day2][Day3][Day4]   ← 吸顶选项卡, 锚点跳转
─────────────────────────────
▼ Day 1 (默认展开)
 ┌─────────────────────────┐
 │ Squat           95 kg   │  ← 大重量 mono
 │ 5 × 5 · rep-out 10      │
 │ sbs · est 1RM 128.50    │
 └─────────────────────────┘
▶ Day 2 (折叠)
▶ Day 3 (折叠)
```

- **Day 选项卡**吸顶 `<a href="#dayN">`，纯锚点，JS 挂了也工作。
- **折叠**用原生 `<details>/<summary>` — 零 JS、离线可靠。
- **深色切换**唯一 JS：`localStorage` 存偏好 + `prefers-color-scheme` 初值。渐进增强 — JS 挂了页面照常只读可用。

### 动作卡片三层

| 层 | 内容 | 样式 |
|---|---|---|
| 标题 | 名字 + 大重量 | 重量 ~1.6em 粗 mono |
| 方案 | `5 × 5 · rep-out 10` | 1.05em |
| 注脚 | `sbs · est 1RM 128.50` | .82em muted |

体重动作显示 `+15 (85)` — 加重 + 工作重量（括号）。

logged 状态保留：已填显示绿色 ✓ + `live_html`（est1RM 变化）；未填灰色"未填"。

## 设计 tokens（复用 ADR 0006）

同一变量集，加深色变体：

```css
:root{--bg:#fff;--ink:#1a1a1a;--muted:#6b6b6b;--line:#e2e2e2;
  --accent:#1f4e79;--up:#2e7d32;--down:#c62828;--radius:3px;--mono:...}
[data-theme=dark]{--bg:#16181a;--ink:#e6e6e6;--muted:#9a9a9a;
  --line:#2c3033;--accent:#6fa8dc;--up:#5cbf60;--down:#e06c6c}
```

卡片 padding 加大 → 汗手容错。

## 数据流 / 错误处理

- 数据流：`_by_day(conn)` → Jinja → 静态 HTML。同现状，零新逻辑。
- 无用户输入，无失败面。
- JS 全包 `try/catch`，挂了静默降级到浅色 + 全展开。

## 测试

- 模板无 Python 逻辑 → 无单测新增。现有 `tests/test_routes_plan.py` 测 `export_week` 路由仍须过（200 + 含重量）。
- 加一路由测试断言新结构存在：响应含 `data-day`、重量值、`<details`。
- 手动：导出开手机/窄窗验证层级 + 深色 + 折叠。

## 不做（YAGNI)

- 离线填次数 + 导出导入（破坏只读分工，改动大）。
- 实时日历判今天（不可靠）。
- 改路由/Python（无必要）。
