# 离线手机端 UI 重设计

日期: 2026-07-24
状态: 已批准（经拷问修订）
范围: `webapp/templates/week_export.html`（离线只读导出页)

## 背景

桌面 webui 已重设计（ADR 0006 极简工具风，见 `static/app.css`）。离线手机导出页 `week_export.html` 仍是旧内联样式：所有字段同权重、小灰字密排、重量这个最关键数字埋在 `.meta` 里。本次从第一性原理重构，非补丁式套样式。

## 第一性原理

此页存在为答一个问题：**"此刻在健身房，这个动作我该上多重、做几次？"**

三个硬约束决定形态：

| 约束 | 推论 |
|---|---|
| 真离线 | 单文件、零请求、零依赖。是特征不是限制。 |
| 只读快照 | 数据回路在桌面（`末组` 输入 + 提交）。手机端刻意无编辑。 |
| 扫读非精读 | 健身房：汗、亮光、组间几秒、常戴护腕。扫一眼 > 读一段。 |

使用动线（每个箭头是摩擦点）:

```
开文件 → 定位下个待练/欠账 Day → 找当前动作 → 读重量+次数 → 上片 → 组间扫下个动作
```

关键洞察：这是**装片清单**，不是数据表。健身房认知单位 = **"多重 × 几 × 几"**。其余字段（mode、est1RM、streak、工作重量）是次级上下文 — 此刻不换一片铁。

## 设计原则

1. **重量即标题** — 一个动作一个大数字，mono，零歧义。
2. **方案即一行** — 动作指令（做几组几次）。状态（streak/est1RM/趋势）全砍。
3. **进度驱动定位** — 默认展开下个待练 day，已练 day 折叠带 ✓。
4. **卡片级进度可见** — 已填末组的动作名字带 ✓ + 绿（done class），未填无标记。中途重导出（练一半）时，day 内一眼分清做了/没做，不靠回忆。只带 done/not-done 信号，不带 logged 值或 est1RM/容量。
5. **亮光高对比** — 浅色 + 大字号 + 充足留白，非深色。

## 架构

改一个模板 `week_export.html`，零路由改动。`_by_day`（`webapp/routes/plan.py:49`）已供全部数据。**无 Python 逻辑改动、整页零 JS** — 纯模板 + 内联 CSS。离线单文件本质保留。

### "默认展开哪个 day" 判定（进度驱动）

设置只有 `week` + `days_per_week`，无"今天星期几"。离线单文件无可靠实时日历。用现有 `logged` 数据推 day 状态机：

- day 状态三态：**全空**（未练）/ **部分填**（练了一半 — 太累/没时间，欠账待补）/ **全填**（练完）。
- **默认展开 = 序号最小的非全填 day**（部分填或全空，取最小 day 号）。按顺序走，遇到欠账/未练自然停在最前。
- 全填完 → 展开最后 day。
- 折叠标题按状态标记，一眼看出欠账：

| day 状态 | 标记 | 含义 |
|---|---|---|
| 全填 | ✓ 绿 | 练完 |
| 部分填 | ◐ 警示色 | 欠账 — 练了一半，待补 |
| 全空 | 无标记 | 未练 |

模板内 Jinja 计算，无需新字段、无日历猜测。折叠 ≠ 删除 — 所有 day 可点开，欠账 day 永远可见。

## 组件

```
Week N 计划
─────────────────────────────
✓ Day 1 (折叠, 练完)
◐ Day 2 (折叠, 练了一半 — 欠账)
▼ Day 2 ... (若 Day2 是最小非全填 → 默认展开, 优先补)
 ┌─────────────────────────┐
 │ Squat           95.0 kg │  ← 大重量 mono
 │ 5 × 5 · rep-out 10      │  ← 方案行
 │ sbs                     │  ← mode tag 注脚
 └─────────────────────────┘
▶ Day 3 (折叠, 未练)
▶ Day 4 (折叠, 未练)
```

- **折叠**用原生 `<details>/<summary>` — 零 JS、离线可靠。
- **无吸顶选项卡**（手机窄屏双倍占空间 + 纯锚点不展开 `<details>` 需 JS，砍）。
- **进度 ✓** 在折叠标题。

### 动作卡片（两层 + mode 注脚）

| 层 | 内容 | 样式 |
|---|---|---|
| 标题 | 名字 + 大重量 | 重量 ~1.6em 粗 mono，完整精度 |
| 方案 | 动作指令一行 | 1.05em |
| 注脚 | mode tag | muted，仅 sbs accent |

**方案行各 mode 措辞**（动作指令，非状态）:

| mode | 方案行 | 说明 |
|---|---|---|
| sbs | `5 × 5 · rep-out 10` | 组×次 + AMRAP 目标 |
| linear_t2 | `8 × 3` | target×sets。砍 streak（状态非指令） |
| linear_t3 | `15 × 3` | t3_target×sets |
| none（纯体重） | `~8 × 3` | 上次次数作参考（`~`前缀）+ 组数 |

**重量显示：**
- barbell / bodyweight：一个大数字 `95.0 kg` 或 `+15 kg`（加重）。**砍工作重量括号** — 总负荷是复盘关注非上片关注，两数字并列汗手易误读（装错=事故）。
- pure_bodyweight：**无大数字**，名字居标题位，方案行撑视觉权重。
- 数字**保留完整精度**（`95.0`/`57.5`）— `rounding=2.5` 量子格点必须可见，不去尾零。

**砍掉的卡片字段**（导出时全空或属状态非指令）：logged 状态、live_html（est1RM 变化预览）、est 1RM、streak、工作重量括号。

## 设计 tokens（复用 ADR 0006）

同一变量集，浅色 only：

```css
:root{--bg:#fff;--ink:#1a1a1a;--muted:#6b6b6b;--line:#e2e2e2;
  --accent:#1f4e79;--up:#2e7d32;--down:#c62828;--radius:3px;--mono:...}
```

重量 ~1.6em 粗 mono。方案行 1.05em。注脚 .82em muted。卡片 padding 加大 → 汗手容错。

## 数据流 / 错误处理

- 数据流：`_by_day(conn)` → Jinja → 静态 HTML。同现状，零新逻辑。
- 无用户输入、无 JS → 无失败面。

## 测试

- 模板无 Python 逻辑 → 无单测新增。现有 `tests/test_routes_plan.py` 测 `export_week` 路由仍须过（200 + 含重量）。
- 加一路由测试断言新结构存在：响应含 `<details`、重量值（`95.0`）、day ✓ 标记。
- 手动：导出开手机/窄窗验证层级 + 折叠 + 默认展开正确 day。

## 不做（YAGNI)

- 深色模式（亮健身房，浅色高对比优先）。
- 吸顶 day 选项卡（折叠列表够定位，且纯锚点不展开 `<details>`）。
- 离线填次数 + 导出导入（破坏只读分工，改动大）。
- 实时日历判今天（不可靠）。
- 卡片显示 est1RM / streak / logged / 工作重量（状态非动作指令）。
- 改路由/Python（无必要）。
